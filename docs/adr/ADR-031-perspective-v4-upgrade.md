# ADR-031: Perspective v4 Upgrade (@finos → @perspective-dev)

**Date:** 2026-06-15
**Status:** Accepted
**Related:** ADR-006 (Analytics Dashboard Milestones), ADR-015 (Analytics Dashboard Wiring), [Perspective v4 Migration Guide](../perspective-v4-migration-guide.md)

## Context

Three dashboard components render through Perspective custom elements:

- `CorrelationMatrix` (`"Datagrid"` plugin)
- `SignalLog` (`"Datagrid"` plugin)
- `LiquidityHeatmap` (`"Heatmap"` plugin, used only when the dataset reaches the
  `perspectiveThreshold` of 10 000 rows; smaller datasets render a hand-rolled
  D3 quadrant view)

They depend on `@finos/perspective ^3.8.0` and three companion viewer packages.
With version 4.0, Perspective moved out of the `@finos` scope into
`@perspective-dev` as part of joining the OpenJS Foundation. The `@finos/*`
packages stop at `3.8.0` — **no 4.x release exists under the old scope** — so
staying on v3 means pinning to an abandoned scope that will eventually emit
deprecation warnings (the maintainers have stated they will deprecate the
`@finos` names after v4.1). The current branch (`feature/upgrade-finos-perspective`)
exists to make this move.

Four facts shaped the decision:

1. **The scope change is mandatory for any forward movement.** The old names are
   frozen at `3.8.0`; security and feature updates are only in the new scope.
2. **The `"Heatmap"` plugin moved packages.** It now lives in the WebGL-based
   `@perspective-dev/viewer-charts`, not in `viewer-d3fc`. Verified in the `4.5.1`
   tarball: `viewer-charts` carries `"Heatmap"` plus `heatmap.frag/vert.glsl`
   shaders and is described as "Perspective.js WebGL Plugin." `viewer-d3fc` still
   publishes (it is at `4.4.1`, lagging) but is effectively deprecated.
3. **The custom element and the narrow API the components use are unchanged.**
   `<perspective-viewer>` is still the registered element; `@perspective-dev/client`
   exports `worker` (named) and `table()` accepts `Record<string, unknown>[]`,
   which is exactly the array-of-objects shape the components pass.
4. **There is a pre-existing runtime caveat.** ADR-015 §Known limitations records
   that under the dev server the v3 WASM asset
   (`perspective-client.wasm`) is not always served (`Missing
   perspective-client.wasm`), so these components are only covered by mocked unit
   tests and the e2e suite asserts the non-Perspective charts instead. v4 renames
   the asset to `perspective-js.wasm` and adds `perspective-server.worker.js`;
   this upgrade is therefore also an opportunity to re-test that known limitation.

## Decision

Adopt `@perspective-dev/*@4.5.1` with the mapping below, and execute it via the
[Migration Guide](../perspective-v4-migration-guide.md).

### Dependency mapping

| Old (`@finos`) | New (`@perspective-dev`) |
| :--- | :--- |
| `@finos/perspective` | `@perspective-dev/client` |
| `@finos/perspective-viewer` | `@perspective-dev/viewer` |
| `@finos/perspective-viewer-datagrid` | `@perspective-dev/viewer-datagrid` |
| `@finos/perspective-viewer-d3fc` | `@perspective-dev/viewer-charts` |

Versions are pinned with a caret (`^4.5.1`), matching the existing `^3.8.0`
convention in `frontend/package.json`.

### `d3fc` → `viewer-charts`, not `viewer-d3fc`

`@perspective-dev/viewer-d3fc@4.4.1` still exists, so this is a choice, not a
forced rename. `viewer-charts` is selected because (a) the `"Heatmap"` plugin —
the only d3fc plugin `LiquidityHeatmap` uses — has moved there, (b) it is the
actively maintained WebGL implementation, and (c) `viewer-d3fc` is lagging at
`4.4.1` with no path to `4.5.1`. The component imports no other d3fc plugin, so
there is no functional loss; the Heatmap rendering moves from SVG/canvas (d3fc)
to WebGL.

### Scope of code change

Eight files: the three components (dynamic `import()` calls), the three specs
(`vi.mock(...)` paths — shapes unchanged, since `worker` remains a named export),
and `package.json` / `package-lock.json` (regenerated by `npm install`). A
repo-wide grep confirms this is the complete set. The refactor is a mechanical
specifier rewrite in those six code files, **not** a blanket repo-wide replace.

### Bundler: webpack, not Turbopack (required)

v4's packaging is incompatible with Next 16's default Turbopack in two ways,
discovered during the Step-6 build verification:

1. **Runtime blob-URL dynamic import.** `@perspective-dev/viewer` boots its worker
   by building a `Blob` from an embedded JS string at runtime and
   `await import(blobURL)`-ing it. Turbopack statically analyzes every dynamic
   import and fails with `Module not found: Can't resolve ('null' | <dynamic>)`,
   with no config to leave a computed specifier as a runtime import. Webpack leaves
   it as a native runtime import (matching v4's own webpack example).
2. **Dist references `src/*.ts` by `.js`.** The published `viewer-datagrid` /
   `viewer-charts` dist imports `@perspective-dev/viewer/src/ts/extensions.js` and
   `column-format.js`, but the package ships only the `.ts` files. Webpack's
   `resolve.extensionAlias` (`.js` → `.ts`) plus `transpilePackages` resolves and
   compiles them.

So the dashboard's `dev` and `build` scripts are pinned to `next ... --webpack`,
and `next.config.ts` adds `transpilePackages` for the five `@perspective-dev/*`
packages, a webpack callback that sets `resolve.extensionAlias` (`.js` →
`[".ts", ".js"]`) and treats the Perspective `.wasm` assets as `asset/resource`.
Turbopack is abandoned for this project as a direct, accepted consequence.

### Verification posture

The unit tests `vi.mock` Perspective entirely, so they prove only that the import
paths rewired — they cannot catch WASM-load, worker-init, theme, or render
regressions. Verified green: `npm run typecheck` (`tsc --noEmit`, the real type
gate — `npm run lint` is `eslint` and does not type-check), `eslint`, all 400 unit
tests, and the production build plus dev-server compile under webpack. The one
check left to a live browser is runtime WASM serving/rendering (see Consequences).

## Consequences

- The dashboard tracks the maintained Perspective line and leaves the
  soon-to-be-deprecated `@finos` scope.
- `LiquidityHeatmap`'s heatmap renders through WebGL (`viewer-charts`) instead of
  d3fc; visually it may differ from the v3 SVG/canvas output and should be checked
  in the browser.
- **Bundler is now webpack, not Turbopack.** The dashboard pins `next dev` and
  `next build` to `--webpack` and adds `transpilePackages` +
  `resolve.extensionAlias` + a wasm `asset/resource` rule in `next.config.ts`.
  Both build and dev compile green under webpack (verified). Tradeoff: webpack is
  slower than Turbopack and is no longer Next's default — accepted to ship v4.
- The v3→v4 refactor itself (package swap, 6-file import/mock rewrite) is verified
  clean: `tsc --noEmit`, `eslint`, and all 400 unit tests pass.
- **The v4 runtime path works in a browser.** The Playwright suite (10 tests,
  chromium + Firefox) passes on a cold webpack dev server; the Charts-section test
  mounts `CorrelationMatrix` against mocked correlation data, so its
  `import("@perspective-dev/viewer")` → worker → table → Datagrid render fires for
  real and produces no app errors. This closes the v3 soft spot for the Datagrid
  path. Still unverified in-browser: the `"Heatmap"` path (`LiquidityHeatmap` only
  enters Perspective mode at ≥ `perspectiveThreshold` rows; the e2e uses small data
  so it renders the D3 quadrant instead) — confirm with a large dataset.
- **Playwright per-test timeout raised 30s → 60s.** A direct consequence of the
  webpack switch: webpack dev compiles the Perspective chunks on demand, and the
  cold first-compilation exceeded the default 30s timeout on Firefox. Bumping to
  60s makes all 10 tests pass on a cold server (set in `playwright.config.ts`).
- The v4 CSS/theme system was redesigned. The components import no Perspective CSS
  today; the e2e Datagrid path renders without a theme import. If the viewer renders
  unstyled elsewhere (e.g. the Heatmap path), add
  `import "@perspective-dev/viewer/dist/css/themes.css"` at the component or layout
  level.

## Alternatives considered

- **Stay on `@finos/perspective ^3.8.0`.** Rejected: the scope is frozen at
  `3.8.0`, will emit deprecation warnings after v4.1, and blocks all future
  Perspective fixes. There is no forward path without the scope move.
- **Map `d3fc` → `@perspective-dev/viewer-d3fc@4.4.1` (the direct analog).**
  Rejected: it is lagging at `4.4.1` (not `4.5.1`), is effectively deprecated, and
  the only plugin we use (`"Heatmap"`) has moved to `viewer-charts`. It would
  reintroduce a stale dependency for a plugin it no longer owns.
- **Use exact pins (`@4.5.1`) instead of carets.** Rejected for consistency: the
  rest of `package.json` uses caret ranges, and Dependabot already manages bumps;
  a caret lets future patch releases flow through the existing process.
- **Load Perspective v4 from CDN at runtime (keep Turbopack).** Inject pinned v4
  CDN `<script>` tags from the components and wait on `customElements.whenDefined`,
  removing the npm packages and all bundler involvement. Rejected: it adds an
  external runtime dependency (CDN availability, CSP), rewrites the component
  loading model, and loses npm-based versioning — a larger change than the verified
  webpack switch, for a placeholder dashboard.
- **Keep Turbopack and find a config workaround for the blob import.** Rejected:
  Turbopack offers no way to leave a computed-specifier `import()` as a runtime
  import, so v4's blob-URL worker boot cannot be made to compile under Turbopack.
